# Cappy video remake

Create an original video on the reference's topic with a stronger explanation and visual storytelling. Preserve the latest user instructions over these defaults. This skill is connected to the local Aiagentbot production project; it is not a standalone renderer.

## Find and run the workspace

The user's highest creative priority is narration-to-action alignment: each spoken idea must have the corresponding visible action at that moment, with meaningful motion continuing naturally into the next idea. Use measured voice/word timings to place action onset, interaction and consequence; equal-length beats alone do not prove synchronization. Never fill speech with recycled scene choreography, unrelated movement or an image wobbling in place. Review these two criteria (semantic synchronization and non-repetition) before decorative polish; preserve the other approved defaults below.

Use `CAPPY_WORKSPACE` when set; otherwise use `D:/workspace/Aiagentbot`. Read applicable AGENTS.md and environment instructions. The helper `scripts/workspace.py` checks the workspace and can launch the existing CLI; do not recreate the backend inside this skill.

Local application: `start-remake.ps1`, `remake_studio.server` on `http://127.0.0.1:8010`, UI `remake_web`, persistent jobs and caches under `data/remake-jobs/<id>`. CLI from the workspace: `python -m remake_studio.cli VIDEO_URL`. Inspect CLI help for supported options before adding flags. Source capture, separate Codex research/script/visual passes, Edge TTS, library music, QA and Remotion export are implemented in `remake_studio.pipeline`. Existing `app/`, `web/` and publishing data belong to another workflow.

For a new link, inspect the source metadata, transcript and representative visual moments before writing. If access fails, record the failure and use other accessible evidence only with clear attribution; never invent having watched the source. A topic alone is insufficient to claim a faithful source analysis.

Keep identifying labels readable for 2–4 seconds or longer when comparisons require it; do not shorten them just to meet shot cadence. ## Coordinate production

For art-quality revisions, read [references/art-direction.md](references/art-direction.md): improve soft illustrated 2.5D subject drawing, materials, lighting and value hierarchy, preserve Cappy, and compare actual renders before claiming improvement or approval.

For improved acting, staging and causal motion, read [references/animation-craft.md](references/animation-craft.md). It adapts useful techniques reviewed from the user's Thanh Hai 2D Studio plugin: pose blending, gaze and contact, movement curves, coherent lighting, layered sets and explanatory shot variety. Preserve Cappy's identity and this workflow's text/music rules. The reference distinguishes implemented keyframe capabilities from rig features requiring code; plugin review does not mean its engine was installed or new footage verified.

The automated web/CLI pipeline defaults to layered SVG artwork. New visual plans require `entity_id` and ordered `keyframes` for every layer: `at` is normalized beat progress 0–1; `x/y` are absolute stage positions; `scale`, `rotation` (degrees) and `opacity` define each pose. Include endpoints and meaningful intermediate phases. Reuse an entity ID across adjacent beats only for the same object, retaining its local geometry and matching boundary poses. Keep legacy layer fields for compatibility. The visual director must plan actual causal motion, not decorative wobble.

Each beat also supplies `labels`, empty when not needed. Each entry is `{text, x, y, target_entity_id, from, duration}`: `x/y` are stage-pixel offsets **relative to the target entity's current position**, unlike absolute layer positions; `from/duration` are seconds relative to the beat start. Match `target_entity_id` to a stable entity in that beat. The renderer draws clean overlay names; SVG `<text>` and lettering baked into generated images remain forbidden. See the identification checks in [references/production.md](references/production.md).

For detailed people, environments or narrative moments that benefit from original raster illustration, the host agent may use the available ImageGen tool, following its skill instructions, then attach those images to the job. This is an optional host-agent step, not an automatic raster-generation capability of the web UI. Read the artwork mapping procedure in [references/production.md](references/production.md) when adding these images; retain prompts and provenance and preserve the short semantic beats. A moving crop of a raster image is illustrative coverage, not a replacement for the required object animation. Research and curate suitable footage/photos separately, recording rights and origin; do not promise automatic online sourcing or reference-video reuse.

Read [references/production.md](references/production.md) for artifact ownership and acceptance checks. Use actual independent agent turns or the pipeline's separate Codex executions for research, writing, direction/assets and QA. Coordinate voice and sound as separate responsibilities; parallelize only independent stages. A set of role names in one prompt is not evidence that independent agents ran. Record actual role execution and outputs. When agent execution is unavailable, report the limitation rather than fabricating a run.

Keep one manifest as the timing contract. Generate voice per scene with content-hash caching, measure actual audio durations, and then retime visual beats. Do not guess narration duration from word count in the final timeline. Preserve voice caches across retries. Verify that background music and effects are present in the exported audio, not merely configured in source.

Use source material for factual research and structural insight; write a new explanation with new wording, examples and shot choices. Track each external asset's URL, creator, license/permission status and attribution needs. Online availability is not blanket reuse clearance. Prefer original illustrations where permission is unknown. Verify factual claims against appropriate primary sources; for medical topics check authoritative health evidence and avoid unsupported treatment claims.

Default to an editable local preview for revision requests. Export an MP4 when requested; a full requested remake through this studio includes an MP4. Keep the editable project, manifest, voice, sources and QA report beside the export. Do not publish to external platforms without explicit authorization.
