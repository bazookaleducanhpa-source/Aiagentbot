# Production handoffs

Use the backend's actual schema and filenames. The artifact names below describe responsibilities, not a second incompatible schema. All agents share a filesystem: assign disjoint paths and one integrator for the final manifest. Record job ID, role, inputs, outputs, execution status and failure details in the job log.

| Role | Reads | Owns | Handoff requirement |
|---|---|---|---|
| Researcher | Reference metadata, transcript, representative frames, primary sources | Research notes, claim/source table, source provenance | Separate supported facts, uncertainty and predictions; identify source's argument without copying script |
| Writer | Research, user constraints | Original English narration and scene intentions | Clear explanation, few jokes, no dependence on displayed prose; claims traceable to research |
| Visual director | Approved narration, style references | Shot plan and semantic beat cues | Multiple visual beats per longer scene, visible explanation of mechanisms, varied framing and expressive mascot |
| Asset artist | Shot plan, approved mascot reference | Job-scoped illustrations, props and asset provenance | Each image depicts the specific spoken idea; no baked-in captions; note generation/source and rights status |
| Voice producer | Final scene text and voice settings | Scene audio/cache and measured timings | Complete intelligible English narration, no truncated words, cache keys include voice and text settings |
| Sound designer | Measured timeline and music library | Music/SFX stems and mix | Cheerful music audible between phrases, narration dominant, relevant effects, clean beginning and ending |
| QA reviewer | Source evidence, manifest, actual rendered frames/audio | QA findings only | Independent review with concrete timecodes, severity and required corrections |
| Integrator | Accepted outputs | Final manifest, Remotion composition and export | Resolve findings, rebuild affected stages only, verify exported file |

Research precedes writing. Direction follows narration; assets and voice may run in parallel after stable text/shot intent. Sound and precise animation timing follow measured voice. QA cannot approve a render it has not inspected. The integrator owns changes to shared schema and package files; other agents must request those changes rather than overwrite each other.

## Checks that matter

**Higher visual density:** Use the scene action/shot inventory to plan distinct wide context, a close-up of the physical process, then a consequence or measurement view. Seek meaningful development roughly every 1.5–3 seconds where narration permits; this is not a hard cutting schedule. Typical actions may resolve around 2.6–3.2 seconds, but comprehension, cue timing and continuous object identity take priority. Keep labels readable for 2–4 seconds or longer for comparisons, carrying them across related shots when appropriate. QA checks whether each added shot contributes a new explanation rather than recycled choreography or cosmetic zoom/wobble. Purposeful art detail must clarify form and mechanism, not bury the faster action in clutter. Report only scenes actually inspected; a new art pass is not implicit user approval.

For focused art-quality work, apply [art-direction.md](art-direction.md). Compare matching actual render frames at full and small sizes; richer subject silhouettes, material distinction and coherent lighting matter more than extra background texture. Keep all timing, motion, labels and music checks in force.

The latest revision requires stronger background floating visibly apparent at normal playback. A useful starting point is approximately 60–110 px over five seconds for the nearest background layer at 1080p, scaled to composition and judged in motion rather than enforced mechanically. Keep overscan and readable contrast. Increase the speed and clarity of causal object actions without moving their spoken cues or accelerating narration; sustain the meaningful process instead of leaving a frozen hold. Refine rounded art, lighting and material separation with the motion.

For music, use all four existing preferred tracks under `output/tesla-cappy-vfacts/public/music`: Cosmic Star Candy, Monkeys Spinning Monkeys, SOSO and Sugar Cookie. Resolve the actual filenames in that folder. Remove the first four seconds from each track only in derived stems/filtering, preserving originals. Sequence all four with smooth crossfades, duck beneath narration, and retain scene SFX. Check the final mix includes every trimmed track and preserves provenance; a file list alone does not prove the audio was mixed correctly.

**Background motion in every video:** Use clearly perceptible layered ambient movement or parallax behind the main action, driven deterministically by frame time. Overscan moving layers, avoid exposed edges and hard-reset seams, and keep continuity across adjacent shots where the setting persists. Background motion must not compete with semantic object action or reduce contrast/readability. Keep section headings in their intended layout and object labels attached to their targets, separate from decorative background transforms. Review motion clips across boundaries as well as representative stills to check hierarchy, label stability, edge coverage and seamless movement.

After requested visual revisions, record concrete user-approved art/layout improvements in the reusable skill, avoiding speculative rules or claims of unattended continuous improvement. The user's “UI” preference here concerns video presentation; it does not expand scope to unrelated web interface changes or scheduled tasks.

**Art and motion acceptance:** Use richer rounded forms, readable materials, coherent lighting and consistent depth across shots. Add detail that explains the subject; avoid busy decoration. Each spoken idea needs a purposeful sequence of anticipation, action and visible consequence. Moving or wobbling an entire still is not a substitute for object animation. Review actual short rendered motion segments as well as stills: check smooth trajectories, clear interactions, pose continuity, and labels staying attached to their subjects without collisions.

For Remotion exports, animation must be deterministic from the current frame and seek correctly to any time. Apply relevant animation-skill guidance selectively; do not stack independent GSAP/Motion playback runtimes into the exported composition. Name only skills actually used, not an unsupported claim that all available skills were applied.

Compare actions across scenes, not only isolated frames. Build an inventory of scene ID, narrated meaning, subject action, interaction and visible result from the visual briefs. Reject duplicated full choreography or footage used as filler under unrelated narration, particularly a repeated scan/extract sequence standing in for scanning, surgery and medication. Asset/character reuse is fine; new colors, labels or camera framing do not make a duplicated causal action distinct. Cite repeated scene IDs and actual timecodes in render QA. Allow deliberate repetition only for an explicit relevant recap, and repair the affected visual brief/action without changing correct narration unnecessarily.

1. **Source and originality:** Accessible source evidence is recorded; narration is independently written. Names, dates, prices and health claims have citations where needed. Predictions remain visibly and verbally distinguishable from facts without requiring a text card.
2. **Visual match:** At representative timecodes, the picture demonstrates what the voice says. Shot changes, object reveals, camera movement and expressions develop the idea. Reject repeated placeholder art, long frozen scenes and empty text endings even if they pass schema checks.
3. **Timing:** Audio metadata determines final scene length. Meaningful visual changes generally occur within about 1.5–3 seconds where narration allows, with motivated exceptions. Ending narration is completely covered by imagery and animation.
4. **Sound:** Listen to beginning, a busy section, a quiet section and ending. Confirm voice, cheerful music and effects survive the final mux; check ducking, clicks, clipping and abrupt cuts. Do not infer audibility from filenames.
5. **Export:** Probe output streams and duration; inspect representative frames and transitions. Link real MP4 and editable preview. A deterministic check cannot replace the independent visual/audio pass.
6. **Spoken intro/outro:** Listen for a concise topic hook and brief Cappy welcome at the opening. After the substantive conclusion, require a specific question about the video topic for comments plus an explicit spoken like-and-subscribe invitation. Check that Cappy gestures and non-text icons/props accompany them without subtitles, word buttons or text end cards.
7. **Entity identification:** Inventory all explanatory foreground objects in every scene, including stars, planets, black holes, tools, clocks, vehicles, organisms and cells. Require accurate English names at introduction, reentry or ambiguity, using 1–4 words generally for 2–4 seconds, longer when needed to read a relationship/comparison. Stage labels so at most 2–3 appear simultaneously. Track their actual subjects through motion and transitions, and never carry a name onto a different object. Confirm identity from narration/evidence: a generic planet is not automatically Earth, nor a generic star the Sun; distinguish virus/bacteria/cell categories correctly. Exempt decorative background stars and incidental scenery. QA must check name coverage in every scene, including nonbiological subjects, and cite missing or wrongly attached names by scene/timecode.
8. **Section navigation:** Group the explanation into clear substantive chapters, not a new section for every shot. Each script scene requires `section_title`: an English 2–5 word semantic heading repeated exactly throughout its contiguous section, with empty intro/outro headings allowed. The renderer places this clean text at a consistent top-left position over the action, persistent for the section or subtly reintroduced on reentry. Verify it remains readable without covering entity labels. These headings are permitted navigation, not subtitles or text-only title cards.

Identification overlays belong in each beat's `labels` array, not inside SVG markup or generated images. Each entry is `{text,x,y,target_entity_id,from,duration}`. `target_entity_id` matches a stable layer entity in the beat; `x/y` are stage-pixel offsets relative to its current position, not absolute coordinates. `from/duration` are seconds relative to beat start and should remain inside the beat. Supply `labels: []` when identification is unnecessary. The renderer owns typography; SVG `<text>` remains forbidden. Entity names and scene `section_title` headings supersede the older blanket no-text preference without permitting paragraphs, captions or text-only endings.

Substantial animation means the subjects act: preparation, interaction and visible consequence with large readable movement and continuous poses across beats. Pan/zoom, wobble and decorative oscillation over a static image do not meet that requirement, including during the introduction and CTA. Illustrated stills and curated footage may provide context but cannot replace the requested animated action throughout the piece.

## Rights and provenance records

For each external photo, video or music item, preserve origin URL/path, author when known, license or permission evidence, attribution requirement, intended use and review status. Treat unknown status as unknown. Generated assets should retain their prompt and references. A source video link authorizes research for this workflow; it does not establish permission to redistribute its footage or voice.

## Directed narration and final package

`remake_studio.voice.synthesize_directed(job, script)` keeps `en-US-GuyNeural`. A scene can provide `voice_segments: [{text,rate,pitch,pause_after}]`, where text segments preserve every narration word in order, rate is a signed integer percent such as `-2%`, pitch is a signed integer Hz such as `+2Hz`, and pause_after is 0–3 seconds. Use slight changes for emphasis instead of dramatic swings. The alternative `voice_direction` is a profile name (or `{profile: name}`): `conversational`, `neutral`, `engaging`, `explanatory`, `emphasis`, `curious`, or `warm`. New directed scenes should explicitly select `conversational`: whole-scene speech at `+1%`, `+0Hz`, with no extra silence. Absent direction still defaults in code to neutral whole-scene speech. The older engaging/explanatory/emphasis/curious/warm presets split at sentence boundaries; avoid using them throughout a film when the goal is connected natural delivery. Profiles do not infer acting or synthesize an emotion style. Read [natural-voice.md](natural-voice.md) for the user's retained delivery approach, meaningful thought groups, reference scope and listening/retiming checks.

The implementation uses Edge TTS supported rate/pitch controls, bounded concurrency and retries, then decodes each phrase to 24 kHz mono PCM. Sample counts and inserted silence determine offsets and total duration before MP3 encoding. Cache keys include text, voice, prosody, pauses and synthesis version. Word offsets are carried into the stitched scene timeline. Listen for awkward phrase joins and excessive pauses before accepting; raw TTS already contains some sentence-tail silence, so pause_after adds to it. Do not promise human-level acting or use unsupported emotion SSML.

For a requested complete video, verify a per-video delivery folder with `video.mp4`, `thumbnail.jpg` or `thumbnail.png`, `title.txt` (chosen attractive truthful title) and a separate alternatives file. Design the thumbnail as a primary deliverable, not an incidental frame dump: original cinematic composition, strong focal hierarchy and readable subject at small size. Inspect reference context without copying logos or exact designs, and ensure both title and image represent the actual video without misleading claims. Link the package and individual main files only after confirming they exist.

## Recovery details

For a verified export with a reviewed thumbnail, use `remake_studio.delivery.package_delivery(job, destination, thumbnail, title=None, alternatives=None)` to create the delivery folder. It requires a real video and supplied thumbnail, writes `video.mp4`, a 1280x720 `thumbnail.jpg`, master artwork, `title.txt`, optional alternatives and available credits/QA. It never substitutes a frame dump for the requested thumbnail. ImageGen production remains a host-agent step; this packager is reusable for later jobs.

Reuse completed stage artifacts only if their inputs still match. A narration edit invalidates affected voice timing, shot timing and mix. An illustration correction does not require regenerating every voice scene. Retry transient operations with a bounded attempt count and retain the error log. Stop the failed dependent stage after retries; show a failed/review-needed state rather than an invented preview or empty successful export.

When editorial QA returns false, the pipeline permits at most two automatic editorial repair attempts. `script-revision.json` is tied to its base script and research inputs; do not apply an old revision to changed inputs. Unchanged scenes retain their reusable caches. If a repair makes no effective change or QA still fails after the attempt limit, record an honest failure with its findings. Optional externally generated artwork is not automatically regenerated by these repairs; review whether affected shots still match the revised narration and request host-agent artwork work only where needed.

## Optional original raster artwork

The web/CLI pipeline generates layered SVG by default. The host agent can generate original bitmap illustrations with the available ImageGen tool when detailed people, environments or story moments need more visual depth. Do not describe this optional agent work as automatic web raster generation. Use the imagegen skill when applicable; preserve the approved mascot identity and avoid generated text.

Save images under the job's `project/public/art/` directory. Save generation prompts, reference sources and provenance in the job alongside the other asset records. Add `artwork.json` at the job root with scene IDs mapped to string beat indexes:

```json
{
  "scene-id-from-manifest": {
    "0": {"file": "art/original-scene.png", "focus": "65% 45%", "zoom": 1}
  }
}
```

Use the actual scene ID and zero-based beat index from that job. Paths are relative to `project/public`; do not put absolute paths in `file`. `build_project` merges these entries into manifest beats. The renderer replaces that beat's SVG shot with the image and pan/zoom treatment. Keep existing short beat durations and narration alignment; use different images, crop focus or other illustrative shots where a long repeated image would become static. Rebuild the project after updating the map and inspect the rendered crop, transitions and mascot placement. Keep SVG for mechanisms and diagrams where object animation explains the idea more clearly.
